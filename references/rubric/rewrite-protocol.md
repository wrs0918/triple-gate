# 两阶段改写协议

适用于「改这章」「去AI味」以及机器门禁 2 轮定向修复仍不过的章节。

## 第一阶段：缺陷清单（只诊断，不动手）

按第三层 rubric 的三个 pass 顺序（叙事 → 话语 → 表面）通读，产出完整缺陷清单写入 `qa/chNNN_rubric.md` 的修订段：

- 每条缺陷：引用原文短语 + 归属 pass + 层次标注（叙事/话语/表面）
- 合并机器报告（`qa/chNNN_gate.json`）的红项与阻断项进同一清单
- **没有清单就开始改 = 违规**。没有缺陷清单的通篇重写会让 AI 指纹更明显，而不是更淡。

## 第二阶段：逐项修复（深层次优先）

1. **先修叙事层**（N 组缺陷）——结构性改动会让表面修改白费。
2. **再修话语层**（D 组）。
3. **最后修表面层**（S 组 + 机器点名的指标/禁词）。
4. 每修完一层，重跑：

```bash
python scripts/tg.py gate --file chapters/chNNN_draft.md --chapter N --previous-file <上一版>
```

   `--previous-file` 传入修改前的版本，用于监控改稿指纹。

## 收尾三测（修完必做）

1. **删除测试**：把改写新增的词划掉，句子是否仍成立？仍成立说明是填料，删。
2. **还原测试**：旧写法是不是更短且同义？是则还原——改得更长往往是在"装饰"。
3. **过度矫正检查**：重跑 `tg gate`，确认指标没有从一侧红灯跳到另一侧红灯（例如 σ² 从均匀修到狂野）。指标落在人类 band 内即可，不要冲极限。

## 修复纪律

- 删除有硬上限：单轮修改删除量不超过全文 35%，禁止整段连删。
- 拿不准的改动标注 `[需复核]` 留给作者，不要自作主张替换成完全不同的写法。
- 同一处 2 轮无新改动即收手，不要无限打磨。

## 反哺

修完的每条"本章教训"（机器 + rubric）提炼进 `changes.json` 的 `anti_patterns_new`，`tg commit` 后自动进入后续章节的「本章禁忌」。
